## 2. Chain layer

| #    | Decision                                                                                                                                                                                                                                                                                                                                                                                           | Status             | Reasoning                                                                                                                                                                                                                                                                                                                                                                       |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2.1  | Native NEAR contract in Rust. One contract account holds everything: Volts, drones, skins, mods, marketplace, packs, settlement. No cross-contract calls.                                                                                                                                                                                                                                          | DECIDED            | Atomic by construction; one deploy; one place for judges and AI reviewers to read.                                                                                                                                                                                                                                                                                              |
| 2.2  | Token standards: NEP-141 (Volts) + NEP-171/177/178/181 (drones, skins, mods) from near-contract-standards 5.29.1, both in the one contract. Not NEP-245.                                                                                                                                                                                                                                           | DECIDED            | The games track hints NEP-245, but NEP-245 has no reference implementation in near-contract-standards (PRs #776 and #950 never merged); the only production code is NEAR Intents' bespoke unpublished crate. NEP-141/171 ship with the SDK, NearBlocks and wallets display them natively, standard events come free. FAQ Q-011: hints are hints. The README states this choice. |
| 2.3  | Token IDs are strings with a type prefix: `d:42`, `s:17`, `m:9`. One NFT namespace, UI filters by prefix.                                                                                                                                                                                                                                                                                          | DECIDED            |                                                                                                                                                                                                                                                                                                                                                                                 |
| 2.4  | Per-drone state on-chain, keyed by token ID, split hot/cold: hot = level, XP, ELO, wins, losses, equipped mod, equipped skin (~64 B, rewritten every race); cold = 9 stats, bound skin and mod lists, total invested. Versioned enums from day one.                                                                                                                                                | DECIDED            | Settlement rewrites 64 B instead of 2 KB; adding a field later needs no bulk migration.                                                                                                                                                                                                                                                                                         |
| 2.5  | Bind rule in the contract: `bind(drone, item)` requires the caller owns both and the item is unbound; permanent. `nft_transfer` written by hand: refuses to move a bound item alone, moves all bound items with the drone, emits one NftTransfer listing every token moved.                                                                                                                        | DECIDED            | The game's ownership rule made unbreakable on-chain.                                                                                                                                                                                                                                                                                                                            |
| 2.6  | Marketplace inside the contract: `list(token, price)` escrows to the contract account, `buy(token)` debits Volts internally, pays seller 90%, treasury 10%, moves the drone with its bound items, emits standard and custom events. `cancel(token)` returns it. Min price 10 Volts.                                                                                                                | DECIDED            | Same rules as the baseline, one on-chain path, no DB-only listings.                                                                                                                                                                                                                                                                                                             |
| 2.7  | Race settlement: `commit_batch(batch_id, seed_hash, matchups)` at matchmaking; `settle_batch(batch_id, seed, results)` three minutes later. Contract verifies `sha256(seed) == seed_hash`, applies ELO, XP, level-ups and Volt rewards, emits one aggregated `race_settled` event per batch. Per-race RNG = `sha256(seed ++ race_id)`; the client can replay.                                      | DECIDED            | Verifiable races without on-chain simulation. The 100-logs-per-call cap is the binding limit. 50 races is roughly 30-55 TGas against a 1,000 TGas ceiling; attach 200.                                                                                                                                                                                                          |
| 2.8  | Pack and capsule opens: `commit_pack(pack_id, hash)` then `reveal_pack(pack_id, secret)` at least one block later; result = `sha256(secret ++ env::random_seed() ++ pack_id)`; items minted in the reveal. Same odds as the baseline.                                                                                                                                                              | DECIDED            | Chain seed alone is producer-influenceable; the commit closes that.                                                                                                                                                                                                                                                                                                             |
| 2.9  | Settlement signer: a function-call access key on the contract account restricted to `commit_batch` and `settle_batch`. If a day is free, a gas key (NEP-611) for the same two methods.                                                                                                                                                                                                             | DECIDED            | The server cannot drain the contract.                                                                                                                                                                                                                                                                                                                                           |
| 2.10 | Storage: fund the contract account with 50-100 testnet NEAR before any player joins. Implement NEP-145 storage_deposit anyway.                                                                                                                                                                                                                                                                     | DECIDED            | Contract pays storage; 1,000 drones is about 21-25 NEAR.                                                                                                                                                                                                                                                                                                                        |
| 2.11 | Events: standard nep141/nep171 for every mint, transfer and burn; custom `hyperdrome` standard for `race_settled`, `pack_committed`, `pack_opened`, `item_bound`, `listed`, `sold`, `cancelled`, `stats_allocated`, `level_up`.                                                                                                                                                                    | DECIDED            | Standard events make assets show in NearBlocks and wallets; custom events feed the live strip.                                                                                                                                                                                                                                                                                  |
| 2.12 | Upgrades: full-access key stays on the contract account during the hackathon; `#[private] #[init(ignore_state)] fn migrate()` from the start.                                                                                                                                                                                                                                                      | DECIDED            |                                                                                                                                                                                                                                                                                                                                                                                 |
| 2.13 | Game constants that affect settlement (payout formula inputs, XP per win/loss, K-factor, level cap) live in the contract, not in admin_config.                                                                                                                                                                                                                                                     | DECIDED            | The server cannot change rewards silently.                                                                                                                                                                                                                                                                                                                                      |
| 2.14 | Template ids are 1-based in SPEC.md 2.5 and 2.6 order (mods 1-26, skins 1-32); 0 means none in `stats_hash` and snapshots.                                                                                                                                                                                                                                                                         | DECIDED 2026-11-02 | SPEC had no numbering, and `stats_hash` already used 0 for an empty slot. Frozen into state at the first deploy.                                                                                                                                                                                                                                                                |
| 2.15 | NFT collection metadata: name "Hyperdrome", symbol "HDROME", spec nft-1.0.0.                                                                                                                                                                                                                                                                                                                       | DECIDED 2026-11-02 | NEP-177 requires both; SPEC named only Volts.                                                                                                                                                                                                                                                                                                                                   |

A method avoids a redeploy to change it.                                                                                                                                                                                                                                                   |
| 2.17 | `bind` is implemented in T3 instead of T5.                                                                                                                                                                                                                                                                                                                                                         | DECIDED 2026-11-02 | The T3 sandbox tests for the bound-item transfer rules need real bound state without test-only code paths.                                                                                                                                                                                                                                                                      |

## 3. Accounts, keys, login

| #   | Decision                                                                                                                                                                                                                                                                                                                                                              | Status             | Reasoning                                                                                                                                                                                                                                                                   |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.1 | Login: Google OAuth and email magic link through Auth.js v5 (already in the baseline with Resend). No wallet UI in the main flow.                                                                                                                                                                                                                                     | DECIDED            | FastAuth v1 is archived (July 2026). NEAR Auth pops an Auth0 approval on every signature. Privy/Web3Auth put the key in the browser so the server cannot sign for the player. Plain web auth plus game-created accounts is the only zero-popup path alive on testnet today. |
| 3.2 | On first login the server creates `p-<slug>.hyperdrome.testnet` in one batched transaction: CreateAccount, Transfer 0.05 NEAR, AddKey full-access (admin, server-held), AddKey function-call scoped to the game contract with a method list and a 1 NEAR allowance. Slug = 8 random bytes in base32, never the email.                                                 | DECIDED            | About 0.06 NEAR per player on testnet. Every player appears as a child of the game account on the explorer.                                                                                                                                                                 |
| 3.3 | Every gameplay mutation is signed server-side with the player's function-call key: allocate, equip, bind, list, buy, cancel, open pack, toggle active. Raw `nft_transfer` and `ft_transfer` stay out of the method list; trades go through the escrow methods.                                                                                                        | DECIDED            | Least privilege. A leaked player key cannot drain items.                                                                                                                                                                                                                    |
| 3.4 | Gas: phase 1, direct signing from the player's 0.05 NEAR float, server tops up under 0.01. Phase 2 (if a day is free), NEP-366 meta transactions relayed by the parent account so players hold 0 NEAR.                                                                                                                                                                | DECIDED            | Trust is identical either way while the server holds the key.                                                                                                                                                                                                               |
| 3.5 | Custody story in the README: server-side scoped keys, AES-256-GCM at rest, admin key under a separate encryption key, one-transaction rotation, and a "claim your account" path.                                                                                                                                                                                      | DECIDED            |                                                                                                                                                                                                                                                                             |
| 3.6 | Account names: `hyperdrome.testnet` owner and treasury, holds the ops function-call key; `game.hyperdrome.testnet` contract and parent of all player and team accounts; players `p-<slug>.game.hyperdrome.testnet`, teams `<name>.game.hyperdrome.testnet`, both created by the contract's `create_player` method so no full-access key is ever loaded by the server. | DECIDED 2026-11-02 |                                                                                                                                                                                                                                                                             |
| 3.7 | Idempotency: every mutation carries a client-generated action_id; the contract rejects duplicates.                                                                                                                                                                                                                                                                    | DECIDED            |                                                                                                                                                                                                                                                                             |

## 7. Not doing, and the one line each gets in the README

- NEAR Intents: mainnet-only (FAQ Q-007). A dry-run 1Click quote for "buy a pack with USDC from any chain" and the documented mainnet path.

- Per-drone sub-accounts: feasible as a showpiece, not the fleet. Token-keyed state satisfies the hint.

## 8. Submission facts

- Code window from 2026-10-19 (FAQ Q-001). Submissions open 2026-11-01 00:00 UTC, close 2026-11-14 23:59 UTC. Results by Nov 18.
- Form or API, once, after the repo is public and the X post is live. Cannot be edited. The `website` field is a spam trap.
- Fields: project name (Hyperdrome), lead name, email, size `1`, tracks `["games","nfts","agents","security"]`, mainnet NEAR address, repo URL, demo post URL, idea (20-2,000 chars), consent true.
- Demo post: public X post saying built at NEAR HACKATHON, with a video (FAQ Q-012: screenshots are not enough). Native video under 2 minutes, repo link in the post. Hosted demo stays up through 2026-11-25.
- LICENSE file required (FAQ Q-014). AI judges screen for reproducibility and feature verification; humans decide (FAQ Q-017).
