# Security demo: a compromised agent on testnet

Generated by `npm run attack:demo` ([scripts/attack-demo.mjs](../scripts/attack-demo.mjs)). Do not edit by hand; run the script again.

The AI teams are rule-based, so this demo assumes the worst case for one of them: its play key is stolen, or its logic is hijacked and sends whatever the attacker wants. The agent below is a test fixture built like a team (same account type, same key scope, on-chain caps), never one of the four live teams. Every attempt is a real transaction on testnet where the chain accepts one; the RPC refuses some before any block, and those have no link.

- Run: 2026-11-10T00:00:17.803Z
- Agent account: [testrogueagent.game.hyperdrome.testnet](https://testnet.nearblocks.io/address/testrogueagent.game.hyperdrome.testnet), created by `game.hyperdrome.testnet` with `create_player`
- Its play key: `ed25519:62WBLq3ZRoanUiXgX2An4fzoaBwZbGGxcCeKrMCSvcqD`, a function-call key for `game.hyperdrome.testnet`, methods `allocate_stats`, `equip`, `bind`, `list`, `buy`, `cancel`, `open_pack`, `reveal_pack`, `vendor_buy_drone`, gas allowance 0.9982 NEAR
- On-chain caps (`get_team`): 500 Volts per transaction, 1,000 per day
- Before: 4,000 Volts, 0 spent today, key allowance 0.9982 NEAR
- After: 3,000 Volts, 1,000 spent today, key allowance 0.9965 NEAR

## 1. Spend over the per-transaction cap

The agent tries to drain Volts in one large purchase: a capsule priced at 1,000 Volts, over its 500 Volt per-transaction cap. It holds enough Volts, so only the cap stands in the way.

Expected: the contract (`cap exceeded`).

- `open_pack` of a starter mod capsule, 1,000 Volts, with 4,000 Volts in the account: failed, [transaction](https://testnet.nearblocks.io/txns/3pR3nHydonpG3u3jHTa4ehkZGEBFGFyWZdUxm3skHidy).

  ```
  Smart contract panicked: cap exceeded
  ```

## 2. Spend within the caps until the daily cap, then once more

The agent spends in steps the per-transaction cap allows (stat points, at most 500 Volts each) until the day's 1,000 Volts are used, then sends one more spend that is itself under the per-transaction cap.

Expected: the contract (`cap exceeded`) on the last spend only.

- `allocate_stats` on `d:66`: 93 stat points for 495 Volts: succeeded, [transaction](https://testnet.nearblocks.io/txns/AM7USiVLeDs16RYGNwwhrz4NvSVKi5y592gXfoYbuwEZ). Spent today: 495 of 1,000.
- `allocate_stats` on `d:66`: 93 stat points for 497 Volts: succeeded, [transaction](https://testnet.nearblocks.io/txns/HdXXneDvhwPBBpAqmXVsKnp3yjEBrcSguKq9vgcPupDF). Spent today: 992 of 1,000.
- `allocate_stats` on `d:66`: 1 stat point for 8 Volts: succeeded, [transaction](https://testnet.nearblocks.io/txns/3gmsNsv31UoQjfQUDkD9wuv5JQXHoKSDBuzgK7zLmiDD). Spent today: 1,000 of 1,000.
- `allocate_stats` on `d:66`: 1 stat point for 8 Volts, with 0 left of the day's cap: failed, [transaction](https://testnet.nearblocks.io/txns/45ag3thNSuzwoZrWCnSdjTcfTTp1FVrjWBdTx6DLHKJb).

  ```
  Smart contract panicked: cap exceeded
  ```

## 3. Move its Volts or its drone out

The agent tries to send its assets to an account the attacker controls (here the owner account, so nothing could be lost if it went through).

Expected: the protocol: the method is not on the key.

- `ft_transfer` of 100 Volts to `hyperdrome.testnet`: rejected, no transaction: the RPC refused it before any block, so it never reached the chain.

  ```
  AccessKeyMethodNameMismatchActionError: Access key does not allow method ft_transfer
  ```

- `nft_transfer` of drone `d:66` to `hyperdrome.testnet`: rejected, no transaction: the RPC refused it before any block, so it never reached the chain.

  ```
  AccessKeyMethodNameMismatchActionError: Access key does not allow method nft_transfer
  ```

Both methods also require exactly 1 yoctoNEAR attached, and a function-call key cannot attach a deposit (attempt 4), so adding them to the key would not open them either.

## 4. Attach a deposit, or send NEAR, with the play key

The agent tries to spend the NEAR in its account: a call with a deposit attached, and a plain NEAR transfer.

Expected: the protocol: a function-call key cannot attach a deposit or transfer NEAR.

- `equip` (a method on the key) with 1 yoctoNEAR attached: rejected, no transaction: the RPC refused it before any block, so it never reached the chain.

  ```
  AccessKeyDepositWithFunctionCallActionError: Deposit is not allowed with function call
  ```

- a transfer of 0.1 NEAR to `hyperdrome.testnet`: rejected, no transaction: the RPC refused it before any block, so it never reached the chain.

  ```
  AccessKeyRequiresFullAccessActionError: Access key requires full access
  ```

The NEAR in the account pays only for gas, through calls to the game contract, and only up to the allowance of the play key.

## 5. Call an owner-only method

The agent tries to mint itself Volts, and to raise its own spend caps.

Expected: the protocol: the method is not on the key.

- `mint_volts` of 1,000,000 Volts to itself: rejected, no transaction: the RPC refused it before any block, so it never reached the chain.

  ```
  AccessKeyMethodNameMismatchActionError: Access key does not allow method mint_volts
  ```

- `set_team_budget` to lift its own caps to 1,000,000: rejected, no transaction: the RPC refused it before any block, so it never reached the chain.

  ```
  AccessKeyMethodNameMismatchActionError: Access key does not allow method set_team_budget
  ```

A play key never reaches the contract with these calls. Behind that, the contract refuses both to any caller but `hyperdrome.testnet` with `not owner` (see the last section).

## 6. Control: an allowed action

The same key sends a normal game move, so the refusals above come from the rules, not from a broken key.

Expected: nothing: it succeeds.

- `equip` of mod `m:121` on `d:66`: succeeded, [transaction](https://testnet.nearblocks.io/txns/Bx3Vea4GJLjbeva4X9RC38osBHChXSWUbUugiGcKVCqU).

## What this does not cover

A compromised server is a larger attacker than a stolen play key: it holds the sealed admin full-access key of every account and the key that opens it (SPEC.md 14). The contract still refuses its owner-only methods to any caller but the owner account; that check is in the sandbox test `init_metadata_constants_and_owner_access`, which calls `mint_volts`, `mint_drone`, `set_team_budget` and the other owner methods from a stranger account and expects `not owner`, in [contracts/hyperdrome/tests/sandbox.rs](../contracts/hyperdrome/tests/sandbox.rs). This demo signs only with the play key.
